# 论文方法到代码

## 实现依据

阅读用户提供的方法、公式、附录及可用官方实现。记录论文版本、公式/算法编号和代码来源。论文与官方代码冲突时说明差异及采用的版本；缺失细节标为假设，不自行补成论文结论。

明确复现目标：验证思路、对齐算法，还是重现数值结果。仅有方法片段时可以完成局部实现，不能宣称复现整篇论文。

## 数据与计算

实现前写清输入输出、张量形状、单位、取值范围及中间表示，例如：

```text
x: [B, C, H, W] → Encoder → z: [B, D]
z → Quantizer → z_q: [B, D], index: [B]
z_q → Decoder → x_hat: [B, C, H, W]
```

逐项核对公式的求和维度、均值分母、边界条件及数值稳定处理。公式不必一一对应 `nn.Module`：无状态计算用函数，有可学习参数或状态时再封装模块。

## 损失与梯度

列出每项损失、权重、更新的参数以及 detach 位置。前向输出正确不代表梯度正确。

例如最近邻向量量化中的 `argmin` 不可导。若采用 straight-through estimator，需明确梯度替代规则；码本使用梯度更新还是 EMA 更新也必须明确。只有重建项和 commitment loss 的片段不足以定义完整 VQ 训练，不应作为可直接运行的实现示范。

多优化器、交替更新、冻结参数或不同训练阶段分别写清更新顺序。按实际输出接口调整 Trainer，不强行套 `model(x)`、`loss(pred, target)` 的单输出模板。

## 实现与验收

- 将符号、公式编号或算法步骤对应到函数及配置项，记录近似与偏离。
- 验证关键算子的手算例子、边界输入和梯度，再运行小规模端到端实验。
- 数值复现需对齐数据、预处理、初始化、训练预算、选模和评估口径；报告与论文的差值及尚未排除的原因。
- 项目位置通常为 `models/`、`losses/`、`datasets/`、`trainers/`、`configs/`；已有仓库沿用原结构。
