# 实验设计与验收

适用于深度学习及计算机领域的研究项目。研究结论需要预先明确的比较对象和评价规则。以下要求按任务选用，记录在项目现有实验计划或 DEVLOG 中。

## 实验协议

- 假设：改动预期影响哪个指标，什么结果支持或否定该假设。区分复现论文数值、验证新方法和工程性能优化。
- 数据：来源、版本、样本数、排除规则、预处理和划分标识。训练集拟合归一化等统计量；验证/测试使用训练所得参数。按实体、序列或时间划分相关样本，检查重复样本与跨集合泄漏。
- 随机性：分别记录数据生成、划分和训练种子。多训练种子比较时固定数据与划分；研究划分波动时单独设计重复实验。
- 指标：定义单位、优化方向、聚合方式、掩码、分母及异常值处理。区分逐样本均值与全数据统计；比值、F1、R² 等不能任意按 batch 平均。
- 选模：预先指定验证指标、早停规则和 checkpoint。测试集只用于配置确定后的最终评估；若无独立测试集，明确报告验证结果。
- 比较：基线与方法使用一致的数据、预处理、评估代码和预算口径；记录训练步数、调参次数、预训练资源及额外数据。结构不同时允许适配超参，但说明调参预算。
- 预算：估计运行数、单次耗时、显存和存储，先小规模试跑。资源不足时缩小实验并说明结论范围，不能自动用短跑替代约定的正式实验。

## 最小正确性验证

- 逐项核对公式、维度、dtype、设备与梯度路径；检查 stop-gradient、广播、归一化和 loss reduction。
- 检查损失和梯度有限，预期训练的参数获得梯度；对关键算子用可手算输入、参考实现或适用的数值梯度校验。
- 小数据过拟合适用于多数监督训练。不涉及训练的算法或系统使用解析解、参考实现、边界输入和任务不变量验证。
- 验证指标与数据划分正确，评估模式和无梯度计算生效。正式实验前验证保存、加载与恢复行为。
- 修复影响结果的 bug 后，标记哪些历史实验失效，仅重跑受影响实验。

## 性能与泛化评估

- 区分理论复杂度、估算开销与实测性能；记录输入规模、工作负载、软硬件环境及重复次数。
- 耗时与吞吐量比较统一精度、batch、预热及设备同步方式，说明是否包括数据读取、预处理与结果后处理。
- 资源指标说明统计范围，如参数量、峰值显存、内存或存储；区分训练成本与推理成本。
- 跨数据集、输入规模或扰动条件比较时，区分固定模型评估与重新训练，记录各条件下可使用的数据和调参预算。

## 完成条件

| 范围 | 需要的证据 |
|---|---|
| 方法实现 | 公式与代码对应、关键正确性验证、可执行入口 |
| 实验验证 | 基线、方法及约定消融的原始结果，可比较的配置与预算 |
| 结论 | 重复实验及波动说明、失败/负结果、适用范围 |
| 复现交付 | 代码版本、环境锁、数据与划分标识、权重、从结果重建表图的命令 |

根据方差、成本和结论强度选择重复次数，报告 n 与每次结果，不能只挑最好种子。标准差与置信区间要注明定义；小样本或单次实验不足以声称统计显著。

交付区分“代码已实现”“小规模检查通过”“正式实验完成”。未运行的命令、不可用的数据和未验证的设备都应明确标出。

训练产物按项目保留策略滚动更新；正式测试结果、论文图表依赖的样本和权重单独归档，避免被周期清理删除。

## 失败与资源限制

遇到 OOM、NaN/Inf、数据错误或中断，先保留错误信息、配置和最后有效存档，再定位原因。不要用替换为零、跳过坏 batch 或无上限重试掩盖问题。

重试需有明确改动和停止条件。改 batch、分辨率、精度或训练预算会改变实验条件，应新开实验并记录；梯度累积也不必然等价于大 batch（如 BatchNorm）。

恢复时核对配置与 checkpoint，确认日志、最佳权重和恢复轮次一致。原子替换只保护单个文件，不保证权重、CSV 和评估文件同时提交；断电或强制终止后需检查缺行、旧摘要及部分写入，不把旧结果当成新一轮结果。

批量实验记录成功、失败、中断及待运行状态，汇总时报告排除项及原因。并发进程不得写入同一个实验目录；重启时只恢复已确认的运行，避免重复执行整组实验。
