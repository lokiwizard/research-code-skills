# 项目约定

## 项目

`{{PROJECT_NAME}}`：默认用 MLP 拟合合成回归数据。替换为真实任务后更新本节，方法假设、数据流和验证结论记入 `DEVLOG.md`。

## 实现

- `train.py`、`eval.py` 负责装配；组件在 `models/`、`datasets/`、`losses/`，训练逻辑在 `trainers/`。
- 实验可变项进入 YAML，注明含义、单位和范围。数学常数无需配置化，新增参数需检查取值与维度。
- 组件通过显式字典和 `build_*` 构建；接口变化时同步调整调用方，不强求训练循环不变。
- 标识符用英文，注释默认中文，解释算法依据、形状、单位与必要限制。优先使用现成算子，不做无用途的包装。

## 实验

- 数据生成、划分和训练种子分开。验证集用于调参和选模，独立测试集用于最终报告；示例仅提供 train/val。
- 改方法后验证前向、梯度、指标和小规模训练，再做正式比较。基线与方法使用可比较的数据、评估协议及预算。
- 每次实验保存有效配置、日志、指标和权重。正式实验补充代码版本、依赖锁、设备及数据划分标识。
- 续训保留原始训练条件，只允许延长总轮数；改变优化策略应新开实验。随机源恢复的效果需实测，不声称跨环境完全一致。
- 权重和训练期间的验证/测试明细保留 best、last 和最近 N 个周期快照，默认 N=3；新档写入成功后清理旧档，best 仅按验证指标选择。配置、标量日志保留完整，正式测试结果另行归档。
- 保留原始标量结果、失败记录和有效测试。只删除本任务产生、可重新生成的临时调试文件。

## 环境与记录

使用项目 uv 环境，提交 `uv.lock`；复现时执行 `uv sync --locked`。下载授权未覆盖时先用已有 `.venv` 或 `uv run --no-sync` 检查环境，再说明所需依赖、数据或权重，按当前授权执行。

每个有意义的改动在 DEVLOG 记录原因、文件和验证结果；未运行检查标明未运行。文档直接写事实和限制，不编造结果或图注结论。这些约定可随项目需要调整。
